# EVFinder 产品需求与开发范围

## 1. 项目目标

EVFinder 帮助电动车车主根据地理位置和充电需求，快速找到、比较并选择合适的公共充电站。平台将公开站点数据与用户评价集中展示，并按距离、接口类型、充电功率和评分等可解释的规则排序，以减少用户搜索与权衡的时间成本。


## 2. 目标用户与使用情境

目标用户是美国的电动车车主，尤其是出行前需要寻找公共充电站、且对接口兼容性和距离有明确要求的用户。

典型情境：用户在出行前输入一个城市或当前位置，希望快速找到附近可用的公共充电站；用户再根据接口类型、距离、功率和已有评分比较候选站点，并决定前往其中一个。

## 3. 核心使用流程

1. 用户输入城市和街道地址，或提交搜索半径；
2. 用户可选择接口类型等筛选条件，并选择距离、功率或评分作为排序依据；
3. 系统返回符合条件的站点列表，列表展示站点名称、地址、距离、接口信息、功率和评分摘要；
4. 用户打开某个站点详情，查看完整基本信息、充电设施信息和评价；
5. 用户可为站点提交评分与评论，后续查询会看到更新后的评分摘要。

“推荐”在初版中指基于明确条件的可解释排序，不包含机器学习个性化推荐。

## 4. 功能范围

### 4.1 初版（MVP）

| 功能 | 说明 | 验收方式 |
| --- | --- | --- |
| 健康检查 | 服务提供健康检查接口，便于确认后端是否启动 | 请求接口返回成功状态 |
| 本地数据库环境 | 通过 Docker Compose 提供隔离且可重复的 MySQL 环境 | 按文档启动后 MySQL 容器状态为 healthy |
| 站点数据导入 | 导入一批美国公共充电站的公开数据 | 数据库存在可查询的站点与接口数据 |
| 站点列表搜索 | 按城市查询；支持接口类型筛选和至少一种排序方式 | 给定条件时，结果仅含符合条件的站点且排序正确 |
| 站点详情 | 查询单个站点的地址、坐标、接口、功率与评分摘要 | 指定存在的站点 ID 返回完整信息；不存在时返回明确错误 |
| 评价 | 提交 1 到 5 分评分和文字评论，并展示评分平均值与评价列表 | 新评价持久化，评分摘要按规则更新 |
| 自动化测试 | 对核心搜索、详情和评价接口有可重复测试 | 测试命令能够通过 |

### 4.2 初版后的增强

- 基于搜索半径的附近站点检索；
- 距离、功率、评分等多种排序方式；
- 大数据量下的联合索引、覆盖索引与游标分页；
- Redis 缓存、缓存失效策略和 Redis GEO；
- 并发提交评价时的事务、幂等与正确性测试；
- 搜索页、详情页、个人中心与搜索防抖；
- Redis 与后端的一键容器化启动、性能报告与部署说明。

## 5. 初版明确不做

- 支付、充电预约、实时充电状态或实时价格；
- 机器学习个性化推荐；
- 复杂用户登录、第三方登录与权限系统；
- 原生移动端应用；
- 声称实时、完整或绝对准确的数据。初版只保证展示已导入公开数据中的内容与更新时间。

## 6. 数据与业务规则

### 6.1 数据来源

初版使用美国公共充电站的公开数据。计划来源为 NREL Alternative Fueling Station 数据/API；实际导入前需确认字段、使用条款、访问方式和更新时间。

### 6.2 必要数据

- 站点：名称、地址、城市、州；
- 充电设施：接口类型；数量和最大功率仅在可信来源提供时展示，未知值保持 `null`；
- 评价：评分（1 到 5）、评论文本、创建时间、站点 ID；
- 评分摘要：评分总和与评价数，可据此计算平均分。

### 6.3 当前假设与待决定事项

- 初版以定期导入的数据为准，不承诺实时状态；
- 初版评价可先通过一个简化的用户标识提交，不做完整注册登录；
- 一位用户对同一站点只能创建一条评价；重复提交幂等地返回原评价，不覆盖第一次内容；
- 数据刷新频率和“可用性/营业状态”字段以数据源实际提供能力为准。

## 7. 技术选择与学习目标

| 技术/概念 | 解决的问题 | 引入阶段 |
| --- | --- | --- |
| Spring Boot | 提供 HTTP API、依赖注入和应用启动能力 | 当前 |
| MySQL | 持久化保存站点、设施和评价之间的关联数据 | MVP |
| JPA / SQL | 完成基础数据访问；复杂查询时学习并使用 SQL | MVP 与搜索增强 |
| 自动化测试 | 防止改动破坏搜索、详情和评价核心行为 | MVP |
| 索引与游标分页 | 在大量站点数据下保持搜索性能 | 搜索增强 |
| Redis | 缓存热点数据和支持地理候选检索 | 缓存阶段 |
| 事务与唯一约束 | 保证评价写入和评分统计在并发下正确 | 评价增强 |
| Docker Compose | 为 MySQL 提供隔离且可重复的本地环境，后续扩展到 Redis 和后端 | 数据库阶段开始 |

## 8. 里程碑

1. 能通过 Maven 编译并启动空的 Spring Boot 服务；
2. 有健康检查 API 及其测试；
3. 通过 Docker 启动 MySQL，建立站点相关表并导入少量演示数据；
4. 完成城市搜索、详情查询和评价 API；
5. 完成初版验收测试与 README 运行说明；
6. 依次加入地理搜索、索引优化、缓存、并发正确性和前端。

## 9. 初版完成定义

满足以下条件时，初版视为完成：

1. 按 README 可在本地启动服务与数据库；
2. 已导入演示站点数据；
3. 可以完成“搜索 -> 查看详情 -> 提交评价 -> 看到评分变化”的闭环；
4. 核心 API 有自动化测试，且测试可重复通过；
5. 文档如实说明数据来源、限制和未实现功能。
